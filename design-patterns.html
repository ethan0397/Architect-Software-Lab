Design Pattern là gì

Design pattern là giải pháp chung, đã được tối ưu hóa, để giải quyết các vấn đề phổ biến khi thiết kế phần mềm trong lập trình hướng đối tượng (OOP). Pattern không phải template cứng nhắc — nó là cách tổ chức code giúp giảm coupling, dễ test, dễ mở rộng và dễ trao đổi trong team.

OOP

Kỹ thuật, không phải ngôn ngữ

Pattern áp dụng được ở Java, C#, TypeScript, Python… Miễn là bạn hiểu class, interface, kế thừa và đa hình.

Prerequisite

Học OOP trước

Nếu bạn mới vào lập trình và chưa vững OOP, nên học nền tảng trước. Pattern chỉ phát huy khi bạn đã quen tư duy object.

Điểm then chốt Pattern không phải mục tiêu. Mục tiêu là giải quyết vấn đề thiết kế — pattern chỉ là công cụ. Tham khảo thêm: Design Patterns là gì? — Viblo

Vì sao nên học design pattern

1

Tăng tốc phát triển

Có sẵn công cụ cho vấn đề thiết kế thông dụng thay vì mỗi lần tự nghĩ từ đầu.

2

Ngôn ngữ chung trong team

Nói "Facade" hay "Observer" là cả nhóm hình dung được cấu trúc, giảm thời gian giải thích.

3

Tái sử dụng code

Áp dụng giải pháp đã được cộng đồng kiểm chứng cho các bài toán lặp lại.

4

Dễ bảo trì, ít lỗi tiềm ẩn

Tránh quyết định thiết kế dễ vỡ về sau; codebase dễ nâng cấp hơn.

23 mẫu Gang of Four (GoF)

Bộ 23 pattern trong cuốn Design Patterns: Elements of Reusable Object-Oriented Software chia thành 3 nhóm theo mục đích sử dụng. Bấm vào từng pattern để xem bài chi tiết.

1. Creational Pattern (Nhóm khởi tạo)

Nhóm Creational Pattern gồm 5 mẫu:

  • Singleton
  • Factory Method
  • Abstract Factory
  • Builder
  • Prototype

Các pattern loại này cung cấp giải pháp tạo object và che giấu logic khởi tạo thay vì dùng new trực tiếp khắp nơi — giúp chương trình linh hoạt hơn khi quyết định object nào cần được tạo.

2. Structural Pattern (Nhóm cấu trúc)

Nhóm Structural Pattern gồm 7 mẫu:

  • Adapter
  • Bridge
  • Composite
  • Decorator
  • Facade
  • Flyweight
  • Proxy

Nhóm này thiết lập quan hệ giữa class và object. Hệ thống càng lớn thì structural pattern càng quan trọng — có thể theo dõi qua class diagram.

3. Behavioral Pattern (Nhóm hành vi)

Nhóm Behavioral Pattern gồm 11 mẫu:

  • Interpreter
  • Template Method
  • Chain of Responsibility
  • Command
  • Iterator
  • Mediator
  • Memento
  • Observer
  • State
  • Strategy
  • Visitor

Nhóm này xử lý quan hệ hành vi giữa các object — có thể theo dõi qua collaboration và sequence diagram.

Creational Patterns

Factory Method

Gom logic tạo object

Dùng khi cần chọn implementation theo config hoặc môi trường.
Abstract Factory

Tạo họ object liên quan

Khi cần bộ UI hoặc bộ provider đồng bộ theo theme/platform.
Builder

Tạo object nhiều bước

Hợp với object có nhiều field optional hoặc quy trình dựng phức tạp.
Prototype

Sao chép object

Khi tạo mới tốn kém; clone từ bản mẫu rồi chỉnh sửa.
Singleton

Một instance dùng chung

Hợp với config hoặc logger gốc, nhưng dễ dẫn tới global state nếu lạm dụng.

Structural Patterns

Adapter

Tích hợp vendor

Chuẩn hóa interface bên ngoài để không làm bẩn domain nội bộ.
Bridge

Tách abstraction khỏi implementation

Thay implementation mà không ảnh hưởng client.
Composite

Cây part-whole

Menu, folder tree, org chart — xử lý leaf và node giống nhau.
Decorator

Thêm logging/cache/retry

Bọc object gốc mà không sửa class gốc.
Facade

Ẩn flow nhiều bước

Gom một use case lớn thành một điểm gọi rõ ràng.
Flyweight

Chia sẻ state chung

Tiết kiệm bộ nhớ khi có hàng nghìn object tương tự (icon, glyph).
Proxy

Kiểm soát truy cập

Lazy load, access control, remote proxy.
Repository

Bảo vệ domain khỏi ORM

Tạo boundary giữa business logic và persistence layer.

Behavioral Patterns

Strategy

Nhiều biến thể hành vi

Tách `if/else` dài thành từng chiến lược độc lập.
Observer

Một event, nhiều phản ứng

Publisher phát sự kiện, subscriber tự xử lý phần của mình.
Command

Đóng gói action

Rất hợp với queue, retry, undo/redo và deferred execution.
State

Hành vi theo trạng thái

Quản lý lifecycle như order, booking, payment.
Template Method

Khung thuật toán cố định

Hợp với import pipeline hoặc workflow có skeleton giống nhau.
Chain of Responsibility

Nhiều bước xử lý nối tiếp

Rất hợp với middleware, validation và approval flow.
Iterator

Duyệt collection

Ẩn cấu trúc bên trong khi client lặp qua phần tử.
Mediator

Gom giao tiếp

Chat room, dialog coordinator — object không gọi trực tiếp lẫn nhau.
Memento

Lưu/khôi phục trạng thái

Undo trong editor, snapshot trước khi thay đổi lớn.
Visitor

Thao tác trên cấu trúc

Thêm operation mới lên nhiều class element mà không sửa chúng.
Interpreter

Grammar nhỏ

Parse biểu thức, rule engine đơn giản.

Chọn pattern nhanh

Nếu bạn thấy...

  • Nhiều `if/else` theo biến thể hành vi -> Strategy
  • Logic `new` nằm rải khắp nơi -> Factory Method
  • Object có nhiều tham số -> Builder
  • API vendor làm bẩn domain -> Adapter
  • Use case gọi 5-7 service con -> Facade

Hoặc bạn thấy...

  • Muốn thêm cache/logging/retry -> Decorator
  • Object có nhiều trạng thái sống -> State
  • Request qua nhiều bước -> Chain of Responsibility
  • Action cần queue hoặc undo -> Command
  • Service dính ORM/SQL -> Repository
